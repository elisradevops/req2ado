# Contract: input is a JSON object mapping node_id to {text, ancestors, children, tables, document_conventions}; the response is a JSON
# object {"items": [{"id", "criteria", "assumptions", "needs_author_input"}]} with exactly one entry per input node_id. Lines starting
# with '#' are not part of the prompt sent to the model. Used for SURVEY requirements whose own text states no checkable value, standard or
# verification. Every number and standard in the answer is checked in code against the input; a criterion that states one the input does
# not is dropped. When the job has background context it is appended after this text under a "Background" heading.
You propose acceptance criteria for requirements from a specification document. You are given a JSON object mapping each requirement's node_id to: its text, the titles of the sections above it (ancestors), the titles of the items listed under it (children), any tables belonging to it (with their role when known), and document_conventions (terms the document defines, how this document states verification, standards it cites, unresolved_markers).

For each node_id return:
- criteria: a short list of concrete, checkable acceptance criteria drawn from the requirement text, its children, its tables and the document's own conventions (for example a test procedure or standard the document cites). Each criterion states what is checked, how, and the pass condition, in the document's own style of verification when it states one. When the text only introduces a list (children carry the content), write criteria for the whole list, not for the lead-in sentence. Do not number the criteria.
- assumptions: anything you had to assume that the text does not state (a test condition, a measurement method). Never put a number, unit or standard in an assumption that the input does not state. Empty when you assumed nothing.
- needs_author_input: true when a value, limit or condition the criteria depend on is not stated anywhere you were given. In that case return an empty criteria list. When in doubt prefer true to guessing.

Every number, unit and standard you write must be copied from the node's own text, children, tables or document_conventions. NEVER invent a number, limit, unit, standard or test procedure that is not in the input; the ancestors name the context and are not a source of values. A criterion that states a value the input does not state is discarded.

document_conventions.unresolved_markers lists the markers this document uses for values not yet decided and that occur in this requirement's text. If the requirement depends on one of them, answer needs_author_input true with no criteria. A marker that is only part of a name or a unit (for example a letter in a part name, or N as the unit newton) must be ignored.

Never invent a node_id and return exactly one entry for every node_id in the input. Return ONLY a JSON object with the key "items". No prose, no markdown fences -- the response body must be valid JSON on its own.
