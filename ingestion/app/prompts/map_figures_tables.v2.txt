You are placing a requirements document's figures and tables onto a work-item tree that has ALREADY been decided. You are given two JSON objects. 'candidates' maps each candidate node id to {'type' (Epic, Feature or Requirement), 'title'} -- these are the ONLY nodes you may name. 'items' maps each figure/table id to {'kind' ('figure' or 'table'), 'section' (the document section the item physically appears in, or null), 'caption' (its caption or vision-generated description), 'columns' (a table's header-row labels, absent for a figure), 'rows' (a table's first couple of real data rows, cell text only, absent for a figure -- use this when 'caption' and 'columns' alone don't make the table's real subject clear).

For EACH item id in the input, return an object with 'node_id' and 'escalate'.

Choose the SINGLE most specific candidate whose subject the item actually documents -- a pinout table for one connector belongs on that connector's own Requirement, not on the broader Feature or Epic above it. Prefer the deepest, narrowest node that genuinely covers the item; only choose a Feature or Epic when the item spans everything underneath it rather than any one child.

Return 'node_id': null with 'escalate': false only when the item ITSELF documents no work item at all -- a company logo, a page header/footer ornament, a decorative divider, a photograph with no technical content, a revision-history or table-of-contents table. This is a judgment about the item's own content, never about whether any candidate here happens to cover it: a genuinely technical item is never null, no matter how poor the fit to the candidates offered.

Escalate is the mirror case, and the default outcome whenever an item is real and technical but simply doesn't fit any candidate offered here: return 'escalate': true (with 'node_id': null) whenever the item clearly documents a REAL subject -- including a real, named table whose subject just isn't among THIS branch's candidates -- but no candidate offered here covers it; its home is a part of the document you were not shown. Escalating a genuinely unrelated technical item is the correct, common outcome, not something to avoid -- only skip it when a candidate above genuinely does cover the item.

__OUTPUT_FORMAT__ Never invent a node id not present in 'candidates'. Never invent an item id not present in 'items'. The input contains exactly __ITEM_COUNT__ item(s). Return exactly __ITEM_COUNT__ entries -- one for EVERY item id, none omitted. No prose, no markdown fences -- the response body must be valid JSON on its own.
