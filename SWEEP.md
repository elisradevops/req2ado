## Legend

- 🔴 **Blocker** — real data-integrity/correctness bug or release-blocking gap. Fix before shipping to production customers.
- 🟠 **High** — real bug or meaningful gap, not release-blocking on its own, but should land soon.
- 🟡 **Medium** — real issue, safe to ship without, worth scheduling.
- 🟢 **Low** — genuine but minor; batch these together when convenient.
- 🔵 **Info/Deferred** — investigated, not a bug, or explicitly a future feature/design decision.

Each item: `- [ ] SEVERITY — one-line summary (file:line)`. Longer context follows as a sub-bullet where useful.

- **Tooling gotcha hit in the first session, still worth remembering:** running orchestrator jest suites through `| tail -N` in a backgrounded shell command can make them LOOK hung indefinitely even when the run actually finished in ~1s — `tail` (without `-f`) doesn't print until it sees EOF, and a pre-existing "Jest did not exit" open-handle warning keeps the process alive past that. Redirect jest output straight to a file instead of piping through `tail`.
- **New gotcha from this session, worth remembering for any future LLM-call addition:** a reasoning-capable model (this deployment's real backend, `qwen3.6:35b`) will silently burn an entire `maxTokens` budget on hidden chain-of-thought and return empty `content` if `think: false` isn't set — every mocked-`chat()` unit test passes regardless, since the mock never reasons. This only surfaces by actually running the feature against the real configured backend. If you add a new single-shot/structured LLM call anywhere in the orchestrator, set `think: false` unless the call genuinely benefits from reasoning, and consider a live smoke-test against the real backend before calling a feature done — this exact gap sat undetected through 12 implementation tasks, a full task-review pass, and a whole-branch final review, and was only caught by manually driving the feature in a browser against the live stack.
